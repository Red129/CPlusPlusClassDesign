校友录管理系统 实验报告
一、	大型实验内容
校友录管理系统（Alumni Management System，AMS）用于管理校友基本信息，校友的信息包括姓名、性别、生日、学号、届级、系、专业、班级、通讯地址、任职单位、 电话、qq、email 等。
校友录管理系统实现了一下主要内容：
1.	进行简单的身份登录，对普通用户和root用户做了区分；
2.	良好的交互感体验，菜单文本，对齐，良好的视觉效果
3.	校友录系统主菜单及功能的选择，初始的文件读取功能；
4.	校友的查询功能，分为靠某关键字段模糊查询和靠学号精确查询；
5.	Root用户对校友的设置功能，可以增加，删除，修改校友信息；
6.	校友录的查看功能，可以便利查看每位校友的基础信息；
7.	校友录的排序功能，可以按照，先届级由小到大再按姓名字典顺序排序；
8.	可以进行性别/年级/院系/专业/班级各项的条件筛选统计，会返回有关信息，并返回统计结果；
9.	主动保存和退出自动保存功能，将操作保存进文件，防止数据丢失，操作无效；
10.	各个数据和合法性检查，同时还有操作的合法检查，即使随便输入系统也不会错误；

（4）校友信息排序的实现：
由于本系统采用单链表存储校友信息，若使用数组排序算法需要频繁移动大量数据。而插入排序只需修改结点指针即可完成排序，能够充分发挥链表插入效率高的特点，因此选择插入排序作为本系统的排序实现方案。由于校友数据采用单链表存储，因此选择了适合链表结构的插入排序算法（Insertion Sort）进行实现。
1. 排序规则
系统按照以下规则进行排序：
1.	优先按照届级（Grade）升序排列； 
2.	当届级相同时，按照姓名（Name）字典序升序排列。 
比较逻辑由 cmps() 函数完成：
2. 排序思路
排序过程中建立一个新的有序链表 sorted。
首先从原链表依次取出结点，然后根据比较规则寻找其在有序链表中的正确位置，并插入进去。随着遍历不断进行，有序链表中的元素数量逐渐增加，最终形成完整的有序链表。
主要步骤如下：
1.	创建空有序链表 sorted； 
2.	从原链表取出当前结点 nowNode； 
3.	保存下一结点位置，防止链表断开； 
4.	判断当前结点是否应插入到有序链表头部； 
5.	若不是头部，则在有序链表中寻找合适插入位置； 
6.	插入结点； 
7.	继续处理下一个结点； 
8.	全部处理完成后，将 sorted 设置为新的头结点。

（7）展示功能实现
- 展示功能用于查看系统中存储的全部校友信息，由 displayAll() 函数实现。该功能通过调用链表类 NodeList 的 display() 方法，从头结点开始依次遍历所有校友节点，并调用每个校友对象的 display() 函数输出详细信息。
为了提高信息的可读性，系统采用表格化格式进行展示，对各字段进行对齐输出，包括姓名、性别、学号、届级、院系、专业、班级、联系方式等内容。展示过程中按照链表存储顺序逐条输出记录，直到遍历结束。
- 该功能实现简单直观，能够帮助用户快速浏览和核对系统中的全部校友数据。
筛选统计功能的实现：
筛选统计功能的实现主要依托于链表遍历与条件判断机制，通过对用户输入的筛选条件进行合法性校验，并结合节点数据逐一比对，实现对校友信息的分类筛选与统计输出。
- 在 Manager::staDisplay() 函数中，首先定义两个变量：flag 用于存储用户输入的筛选字段（如“性别”“年级”“院系”“专业”“班级”），count 用于统计符合条件的记录数量。系统提示用户输入筛选条件后，对输入进行循环校验，确保其属于预设的五种合法字段之一。如果输入不合法，则要求重新输入，直到满足条件为止。
随后，系统要求用户输入关键词 keywords，并同样进行非空校验，确保查询条件有效。
- 在数据处理阶段，系统从链表头节点 nl.getHead() 开始遍历整个单链表，通过 while(nowNode != nullptr) 逐个访问每一个校友节点 nowNode。对每一个节点，系统根据用户选择的筛选字段进行条件匹配判断，例如：
•	若筛选字段为“性别”，则比较 nowNode->data.getSex() 与关键词是否相等 
•	若为“年级”，则比较 getGrade() 
•	若为“院系”，则比较 getDepartment() 
•	若为“专业”，则比较 getMajor() 
•	若为“班级”，则比较 getClassNum() 
当某个节点满足条件时，调用 display() 函数输出该校友的完整信息，并执行 count++，用于累计符合条件的记录数量，同时在每条记录之间输出分隔线增强可读性。
遍历结束后，系统输出统计结果，格式为“共统计到X条有关信息”，其中 X 即 count 的最终值。

刚开始的时候，我觉得增删查改应该不难，但真正开始写之后才发现很多细节比想象中复杂。例如链表节点的连接与删除、文件数据的保存与读取、输入错误后的处理、排序逻辑的实现等，都花了不少时间调试。有些问题看起来很简单，比如输入邮箱后程序卡住、查询没有结果、排序顺序不正确等，实际上定位原因花了很久。通过不断输出调试信息、阅读报错信息和修改代码，我逐渐学会了如何分析问题和解决问题，大概是这样。
在本项目中，我运用了类与对象、继承、链表、文件流、函数模板、运算符重载等知识。其中印象最深的是链表部分。以前只是会做课本上的链表题，而这次是真正把链表应用到项目中，实现了校友信息的增加、删除、查找和排序，对链表的理解比以前深入了很多。同时也体会到了面向对象设计的好处，例如把 Person 作为基类，把校友类设计为派生类，可以减少重复代码，让程序结构更加清晰。
后来在系统中又增加了管理员登录、权限控制、修改功能以及输入合法性检查等内容。虽然这些新增的功能并不复杂，但让我意识到一个真正能使用的程序不仅要实现功能，还要考虑用户输入错误、权限管理以及数据安全等问题。
- 当然，目前的系统仍然有一些不足。例如查询功能仍然采用顺序遍历，当数据量较大时效率不高；管理员密码直接写在程序中，不够安全；界面也只是简单的命令行界面。如果以后继续完善，我希望能够尝试使用模板类改造链表，使用 STL 容器优化代码，甚至增加图形界面和数据库支持。
- 通过这次课程设计，我最大的收获并不是学会了某一个具体知识点，而是体会到了从需求分析到代码实现再到调试测试的完整开发过程。很多知识以前只是停留在课本和作业层面，而这次真正把它们组合起来完成一个项目后，才发现自己对 C++ 的理解更加深入了，也提高了独立解决问题的能力。虽然过程中经常因为 Bug 熬夜调试，但当程序最终能够正常运行时，还是很有成就感的。
